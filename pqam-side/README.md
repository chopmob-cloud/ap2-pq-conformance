# pqam-side: cross-implementor cases for the v1 signed input

18 v1 artefacts over the AlgoVoi `mandate_body` (unchanged), generated by an implementation written independently of
`algovoi-side/verify_v1.py`, as offered on [AP2 #250](https://github.com/google-agentic-commerce/AP2/issues/250).

```
signed_input = "AP2PQC/1.0/" + object_type + 0x00 + jcs(mandate_body) + 0x00 + jcs(signer_set)
```

## The implementation

[`ap2pqc-v1.mjs`](https://github.com/eltociear/pqam/blob/main/interop/ap2-pq-conformance/ap2pqc-v1.mjs) is JavaScript
written from `algovoi-side/README.md` and `verify_v1.py`, sharing no code with this repository. It has its own JCS,
ES256 (P-256, DER), Ed25519, ML-DSA-65 and Falcon-1024 (noble libraries). It applies the same fail-closed rules: every
listed signer present with a matching `key_id`, an unlisted signer is an error, and an unknown algorithm or object type is
an error, never a skip.

Run on `algovoi-side/ap2-pqc-v1-algovoi-side.json` (at `aea0f2c`), it reproduces the 501 JCS bytes
(`expected_jcs_bytes_hex`), and all three signatures verify: ES256, Ed25519 and Falcon-1024. `ap2-pqc-v0-algovoi-side.json`
is refused under the v1 rules.

## The cases (`pqam-cross-v1.json`)

| Group | Signers | Cases |
|---|---|---|
| A | ES256 + Ed25519 | `valid`, `strip_ES256`, `strip_Ed25519`, `strip_Ed25519_and_rewrite_descriptor`, `relabel_object_type`, `key_id_mismatch`, `unlisted_extra_signer`, `unknown_algorithm_in_descriptor`, `body_edited` |
| B | ES256 + ML-DSA-65 | the same nine for the PQ hybrid. `strip_ML-DSA-65` is the Q-Day downgrade |

- `expect` gives `ok`, and for failures a substring of the error `verify_v1.py` prints.
- Group B also carries `expect_verify_v1_without_mldsa65`, the fail-closed result for a verifier that cannot check
  ML-DSA-65, which is `verify_v1.py` as published.
- Keys come from the seeds in the file. ES256 and Ed25519 use the AlgoVoi v1 derivation, `private_key = sha256(seed)`.
  ML-DSA-65 is FIPS 204 keygen with `xi = sha256(seed)`, pure, empty context, with deterministic signing. The file
  rebuilds byte for byte: `node interop/ap2-pq-conformance/build-cases.mjs` in eltociear/pqam.

**Checked by the independent implementation only.** These cases have not yet been run through `verify_v1.py`. Any
disagreement between the two is a finding.

Test keys only. Never use them for anything else.
